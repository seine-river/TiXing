# Feature Specification: TiXing 工程全面优化（安全/数据/性能/功能/质量）

**Created**: 2026-08-25  
**Status**: Draft  
**Input**: 用户请求"Review 整个工程并给出优化建议，确认后进入修改阶段"；用户已确认纳入全部五个批次（A 安全合规 / B 数据与功能 / C 性能 / D 功能收口 / E 代码质量与 UI 债），并确认：API Key 采用"本地配置文件+不入库"方案、Git 历史仅吊销 Key 不重写。

## Overview

本次优化针对现有错题管理应用 TiXing 的全面工程整改：消除密钥与签名材料泄露风险；建立可见、可靠的错误处理与数据写入保障（复习提交原子化、首屏数据可靠加载、导入导出完整可信）；修复提醒功能不可用与叠加问题；补齐性能基础设施（数据库索引、聚合查询、懒加载、图片降采样、资源释放）；收口"配置先行、实现缺位"的半成品功能；清偿 UI 与代码质量债（深色模式资源化、公共组件提炼、巨型页面拆分、数据库工程化、死代码清理）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 安全合规整改 (Priority: P1)

开发者/维护者视角：密钥与签名材料不再随仓库与安装包泄露。API Key 从源码移入本地配置文件（不入库），签名密码移出版本库，Key/ 目录与构建杂物被 gitignore 覆盖，release 包启用代码混淆。

**Why this priority**: 已入 git 历史 + 未混淆的发布包意味着密钥随时可被盗刷，属最高风险，必须最先整改。

**Independent Test**: `git grep` 源码与配置中不再出现 API Key/密码明文；`git status` 不再出现 Key/、.DS_Store 等待误提交文件；构建产物为混淆包。

**Acceptance Scenarios**:

1. **Given** 仓库当前状态，**When** 完成整改，**Then** AiService 源码及全部入库文件中无 API Key 明文，Key 从本地配置文件读取，且该配置文件被 .gitignore 忽略。
2. **Given** build-profile.json5 含签名密码明文，**When** 完成整改，**Then** 密码不再入库，本机构建仍可正常签名。
3. **Given** Key/ 目录含发布私钥，**When** 完成整改，**Then** .gitignore 覆盖 /Key/、/.cache/、.DS_Store、/App截图/，且已被追踪的构建缓存从版本库移除。
4. **Given** release 构建未混淆，**When** 完成整改，**Then** release 构建启用混淆且应用功能回归正常。

---

### User Story 2 - 数据写入可靠与错误可见 (Priority: P1)

学生视角：录入错题、提交复习结果、获得积分时，任何失败都能被如实感知，不会"显示成功实则丢失"；复习提交不再产生状态覆盖；应用冷启动首屏能可靠加载数据而非偶发空白。

**Why this priority**: 复习记录与积分是产品核心价值，静默丢失是致命缺陷；首屏空数据直接损害第一印象。

**Independent Test**: 构造数据库写入失败场景（如注入失败/异常），页面显示失败提示而非成功；冷启动反复进入首页数据均正常显示。

**Acceptance Scenarios**:

1. **Given** 数据库插入失败，**When** 学生保存错题，**Then** 页面提示失败且不显示"录入成功"。
2. **Given** 一道题即将达到掌握条件，**When** 学生提交最后一次复习结果，**Then** 复习日志、积分、错题状态按正确顺序落库，MASTERED 状态不会被后续写入覆盖回 REVIEWING。
3. **Given** 应用冷启动，**When** 首页立即加载，**Then** 页面等待数据库就绪后展示数据，不出现空列表假象。
4. **Given** 数据库初始化失败，**When** 应用启动，**Then** 有明确的日志与用户可见提示，而非静默运行在无数据库状态。

---

### User Story 3 - 复习提醒真实可用 (Priority: P1)

学生/家长视角：保存提醒设置后系统弹出运行时权限申请，授权后提醒真实发布；重启应用不会产生重复提醒；保存结果提示与真实结果一致；提醒时间段可以在页面上真实修改。

**Why this priority**: 提醒功能当前整体不可用（权限缺失）且有副作用（无限叠加），属核心功能失效。

**Independent Test**: 真机/模拟器上保存提醒设置→弹出权限→授权→通知中心出现提醒；重启应用→提醒不重复；点击时间段可修改并保存成功。

**Acceptance Scenarios**:

1. **Given** 首次保存提醒设置，**When** 点击保存，**Then** 系统弹出 PUBLISH_AGENT_REMINDER 运行时权限申请，授权后提醒发布成功。
2. **Given** 应用重启（reminderId 内存丢失），**When** 再次应用提醒设置，**Then** 旧提醒被查询并取消，不产生重复提醒。
3. **Given** 提醒发布失败（如权限拒绝），**When** 保存设置，**Then** 页面如实提示失败原因，不显示"设置已保存"。
4. **Given** 提醒设置页展示"点击时间可修改"文案，**When** 点击时间段，**Then** 弹出时间选择器，可修改并保存生效。

---

### User Story 4 - 数据导入导出完整可信 (Priority: P1)

家长视角：导出的备份包含全部数据（错题+复习记录+图片），导入后复习历史完整；导出失败时如实报错；大文件解析不卡死界面。

**Why this priority**: "换机不丢学习记录"是数据管理的核心承诺，当前导入丢复习记录、导出假成功。

**Independent Test**: 导出→清空→导入，错题数、复习记录数、图片均与导出前一致；选择超大备份文件解析时界面保持响应。

**Acceptance Scenarios**:

1. **Given** 存在错题及其复习记录，**When** 导出并导入，**Then** 复习记录按错题关联完整恢复（含去重），不静默丢失。
2. **Given** 导出时写文件失败，**When** 导出流程结束，**Then** 页面提示失败，不显示"导出成功"。
3. **Given** 导出文件中 imageUrl 为本机绝对路径，**When** 在另一台设备导入，**Then** 错题图片随备份包迁移并可正常显示。
4. **Given** 用户选择了超大备份文件，**When** 解析预览，**Then** 解析在后台执行，UI 不冻结，并有大小上限保护。

---

### User Story 5 - 误操作保护与数据一致性 (Priority: P2)

学生视角：滑动删除错题前有二次确认；重新识别更换图片后，新图片路径正确保存。

**Why this priority**: 误触即永久丢数据不可接受；UI 与数据库不一致会造成后续显示异常。

**Independent Test**: 滑动点击删除→出现确认框→确认后才删除；详情页拍照重识别→保存→重新进入详情页图片仍为新图。

**Acceptance Scenarios**:

1. **Given** 错题列表，**When** 滑动点击删除，**Then** 弹出确认对话框，仅确认后执行删除（删除本身为原子操作，含关联复习日志）。
2. **Given** 错题详情页，**When** 重新拍照识别并保存，**Then** imageUrl 更新落库，重新进入页面显示新图片。

---

### User Story 6 - 半成品功能收口 (Priority: P2)

学生/家长视角：OCR 低置信度时出现人工核对提醒；连续学习天数（streak）真实计算并与积分联动；每日复习上限与科目开关真实生效；科学错题可被自动标注；语文题不再被误判为数学；判分不受全半角/空格/大小写影响。

**Why this priority**: 这些是"配置可见但实现缺位"的功能，用户可感知落差。

**Independent Test**: 构造低质量图片 OCR→出现核对提示；连续两天使用→streak 变为 2 且发放连击积分；设置每日上限 5→复习队列最多 5 题；含"（1）"的语文文本→判定为语文。

**Acceptance Scenarios**:

1. **Given** OCR 返回结果置信度低于阈值，**When** 识别完成，**Then** 界面出现"需人工核对"提示。
2. **Given** 用户连续多天使用应用，**When** 查看积分中心，**Then** 连续学习天数真实递增，连击积分按规则发放（仅一次/天）。
3. **Given** 提醒设置中开启每日上限与科目开关，**When** 进入复习，**Then** 复习队列按上限截断、仅含启用科目的错题，且按当前学生过滤。
4. **Given** 含全角括号编号的语文题文本，**When** 自动检测学科，**Then** 判定为语文而非数学；含科学特征文本可标注为科学。
5. **Given** 标准答案与用户答案仅存在空格/全半角/大小写差异，**When** 提交答案，**Then** 判定为正确。

---

### User Story 7 - 性能与资源优化 (Priority: P2)

学生视角：数据量增长后列表、统计、复习、导入导出保持流畅；拍照流程不泄漏文件句柄与内存；临时文件不无限累积。

**Why this priority**: 当前零索引+全量内存统计+整图解码的架构随数据增长必然劣化。

**Independent Test**: 构造大量数据（如 500+ 错题）后各页面滑动与加载流畅；反复拍照取消后 filesDir 无残留半成品文件。

**Acceptance Scenarios**:

1. **Given** 高频过滤字段（nextReviewDate/studentId/mistakeId 等），**When** 数据库创建，**Then** 存在对应索引。
2. **Given** 首页/报表/运营/错题四页统计数据，**When** 加载，**Then** 使用数据库聚合查询而非全量加载内存过滤。
3. **Given** 错题列表数据量较大，**When** 滚动列表，**Then** 使用懒加载，内存平稳。
4. **Given** 列表缩略图组件，**When** 加载图片，**Then** 按显示尺寸降采样解码，不整图解码。
5. **Given** 图片处理流程异常中断，**When** 流程结束，**Then** 文件句柄关闭、PixelMap 释放，无残留临时文件。

---

### User Story 8 - 代码质量与 UI 债清偿 (Priority: P3)

开发者视角：颜色资源化并支持深色模式；页面间重复代码提炼为公共组件；CapturePage 巨型组件拆分；数据库具备事务与版本化迁移；死代码清除；文案统一走资源常量。

**Why this priority**: 不影响当前功能正确性，但决定长期维护成本与上架品质（深色模式下当前观感割裂）。

**Independent Test**: 系统切换深色模式→应用配色正确跟随；CapturePage 拆分后各步骤独立可维护；数据库升级走版本号迁移；无未使用的导入/死状态。

**Acceptance Scenarios**:

1. **Given** 系统切换深色模式，**When** 浏览全部页面，**Then** 配色正确适配无刺眼白块。
2. **Given** 页面间 11 类重复模式（渐变头图、错题卡片、Chip 筛选、主按钮、空态、卡片容器等），**When** 完成提炼，**Then** 公共组件被各页面复用，样式统一。
3. **Given** CapturePage 1082 行巨型组件，**When** 完成拆分，**Then** 各步骤为独立子组件，状态互不污染。
4. **Given** 数据库结构升级需求，**When** 新版本启动，**Then** 按 PRAGMA user_version 版本号执行迁移，仅执行一次，失败可感知。
5. **Given** 全部已知死代码（resetMastery、未用的 RouteParams、死状态、未使用导入等），**When** 完成清理，**Then** 编译零警告，代码中无不可达功能配置。

### Edge Cases

- 多学生场景：复习队列、积分、提醒设置按 studentId 隔离，不串号。
- 数据库为空/首次启动：种子数据完整写入（原子），页面显示空态而非报错。
- 媒体选择器授权过期 URI：不作为持久化路径使用，拷贝失败时明确报错而非降级使用临时 URI。
- 导入文件格式非法：校验 app 标识与版本号后才解析，超限文件直接拒绝并提示。
- 深色模式下图片/图表颜色仍可读。

## Requirements *(mandatory)*

### Functional Requirements

**安全与配置（批次 A）**

- **FR-001**: 系统 MUST 将 AI 服务密钥移入本地配置文件（不入库、被 gitignore 覆盖），运行时从该文件读取；文件缺失时给出明确指引提示而非崩溃。
- **FR-002**: 构建 MUST 移除入库的签名密码（本地保留或使用本地配置），.gitignore MUST 覆盖 /Key/、/.cache/、.DS_Store、/App截图/，已被追踪的构建缓存 MUST 从版本库移除（保留本地文件）。
- **FR-003**: release 构建 MUST 启用代码混淆（沿用已有 obfuscation-rules），且混淆后应用回归可用。
- **FR-004**: 模块权限声明中 INTERNET MUST 补充 reason 资源（对齐项目自身约定）。

**数据可靠与错误可见（批次 B 核心）**

- **FR-005**: 持久层所有写操作（插入/更新/删除/迁移/种子）MUST 不再静默吞错：失败时记录日志并向上返回失败结果；关键用户操作（保存错题、提交复习、保存设置、导入导出）失败时页面 MUST 显示失败提示。
- **FR-006**: 复习提交流程 MUST 原子化编排（插入日志→判掌握→更新状态按序完成，积分与状态更新不互相覆盖）。
- **FR-007**: 数据库初始化 MUST 提供就绪机制，页面查询在就绪前等待；初始化失败 MUST 有用户可见提示与日志。
- **FR-008**: 错题删除 MUST 二次确认，且删除错题与其复习日志 MUST 在同一事务中完成。

**提醒功能（批次 B）**

- **FR-009**: 保存提醒设置前 MUST 通过运行时权限申请获取 PUBLISH_AGENT_REMINDER；发布/取消失败 MUST 如实反馈。
- **FR-010**: 应用启动应用提醒设置时 MUST 先清理本应用旧的有效提醒（或持久化 reminderId），确保提醒不叠加。
- **FR-011**: 提醒设置页时间段 MUST 可通过时间选择器修改并保存生效；"行动按钮"点击行为与文案一致（拉起复习）。
- **FR-012**: 复习队列 MUST 按当前学生过滤，并消费每日上限与科目开关设置。

**导入导出（批次 B）**

- **FR-013**: 导出 MUST 包含错题、复习记录与错题图片；导入 MUST 按关联恢复复习记录（含去重）并恢复图片；导出/导入失败 MUST 如实报错。
- **FR-014**: 导入文件解析 MUST 校验应用标识与版本，MUST 在后台线程执行且有大小上限。

**功能收口（批次 D）**

- **FR-015**: OCR 置信度 MUST 来自真实识别结果（或按结果质量真实评估），低置信度核对提醒 MUST 可触发。
- **FR-016**: 连续学习天数 MUST 真实计算（按日去重），连击积分按天发放且不重复；展示处与积分一致。
- **FR-017**: 学科检测 MUST 修正全角括号误判，MUST 支持科学学科识别；判分 MUST 对答案做归一化比较（trim/大小写/全半角）。

**性能与资源（批次 C）**

- **FR-018**: 数据库 MUST 为高频过滤字段建立索引（mistake.nextReviewDate/studentId、review_log.mistakeId、points_log.studentId、analytics_event.eventType、knowledge_profile.studentId、redemption.studentId）。
- **FR-019**: 状态统计类查询（总数/已掌握/复习中等）MUST 使用 SQL 聚合；错题列表 MUST 支持懒加载；列表图片 MUST 按显示尺寸降采样。
- **FR-020**: 媒体服务 MUST 在异常路径释放文件句柄与 PixelMap，MUST 提供临时文件清理（拍照取消/失败、错题删除联动、导出目录限量）。
- **FR-021**: 知识画像重算 MUST 避免每题全表重算（会话结束一次性重算或增量）；聚合查询不再全表加载内存过滤。

**质量与 UI 债（批次 E）**

- **FR-022**: 颜色 MUST 迁移为 color 资源并提供 dark 模式配色；EntryAbility 深色模式行为与配色一致；页面出现硬编码 hex 颜色 MUST 清零（收敛至资源引用）。
- **FR-023**: 页面公共模式（渐变头图、错题卡片、Chip、主按钮、空态、卡片容器、页面骨架）MUST 提炼公共组件并被复用。
- **FR-024**: CapturePage MUST 拆分为步骤子组件，各步骤状态独立；异步回调 MUST 有页面销毁防护。
- **FR-025**: 数据库 MUST 引入 PRAGMA user_version 版本化迁移（替代启动跑全量 ALTER），关键多表写 MUST 使用事务。
- **FR-026**: 死代码 MUST 清理（不可达枚举配置一并处理：实现或移除）；未使用导入/死状态清零；页面间重复工具函数（标题截断、日期格式化、状态统计）统一收敛。
- **FR-027**: 图片重识别保存后 imageUrl MUST 正确落库（updateMistake 支持该字段）。

### Key Entities *(include if feature involves data)*

- **AiServiceConfig**: 本地密钥配置（不入库文件），含 API Key 与模型名；缺失时的降级行为。
- **ReviewSubmitContext**: 一次复习提交的完整上下文（错题、日志、判分结果、状态流转、积分）——原子编排的对象。
- **ReminderState**: 提醒生命周期状态（已发布 reminderId、设置快照），支持跨重启幂等。
- **BackupBundle**: 导出包（错题+复习记录+图片+元数据 app/version），导入校验与恢复的依据。
- **DbMigration**: 版本化迁移描述（版本号、DDL 集合），替代现有全量 ALTER 模式。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 入库文件与发布包中不存在任何明文密钥/密码（git grep 与包内检查均无命中）。
- **SC-002**: 全部关键写路径（保存错题/提交复习/保存设置/导入导出）在失败场景下 100% 如实提示，零"假成功"。
- **SC-003**: 冷启动首屏 20 次连续测试零空数据现象；复习提交 100 次零状态覆盖（MASTERED 不回退）。
- **SC-004**: 真机提醒链路（授权→发布→重启不叠加）100% 可用；时间段修改保存生效。
- **SC-005**: 导出→清空→导入往返后，错题数、复习记录数、图片可用数一致率 100%。
- **SC-006**: 500 条错题规模下，首页/报表/列表加载与滚动无可感知卡顿（对比优化前）。
- **SC-007**: 系统深色模式下全部页面无未适配白块；页面硬编码颜色数量降为 0。
