## 1. 总体架构

题醒当前是 **本地优先的单机应用**。业务数据、文件资产和备份能力都在设备沙箱内完成；只有生成类 AI 能力调用外部 GLM 服务。

```text
┌─────────────────────────────────────────────┐
│ ArkUI Pages / Components                    │
│ 首页、错题、复习、问一问、好奇星球、我的      │
├─────────────────────────────────────────────┤
│ UseCases                                    │
│ 排期、掌握、提交、积分、统计、兴趣聚合        │
├─────────────────────────────────────────────┤
│ Repository                                  │
│ DatabaseHelper / relationalStore / dbHelper  │
├─────────────────────────────────────────────┤
│ Services（平台能力适配）                     │
│ Media / AI / Audio / Speech / Reminder / IO  │
└─────────────────────────────────────────────┘
              │                │
              │ 本地文件        │ HTTPS
              ▼                ▼
     应用沙箱资产         智谱 GLM API
```

### 1.1 架构原则

1. **本地数据权威**：错题、复习、积分、问一问和报告以本地数据库为准。
2. **AI 辅助而非权威**：AI 输出必须经过用户核对或本地确定性算法约束。
3. **平台能力隔离**：页面不直接绑定系统能力，统一通过 Service 适配。
4. **单例仓储**：`dbHelper` 是唯一 `DatabaseHelper` 实例。
5. **失败可见**：写操作返回 `DbResult`，系统能力失败向页面返回可执行原因。
6. **跨平台目录隔离**：DevEco Studio 只打开 `harmonyos/`，Android Studio / Xcode 后续只打开各自平台目录。

## 3. HarmonyOS 模块分层

```text
entry/src/main/ets/
├── models/       # 纯数据模型与枚举
├── repository/   # DatabaseHelper，唯一数据访问层
├── usecases/     # 业务规则与编排
├── services/     # AI、媒体、音频、语音、提醒、备份等能力适配
├── components/   # 复用 UI 组件
├── pages/        # 页面与流程编排
└── common/       # 配置、上下文、常量、通用结果、WAV 工具
```

依赖方向：

```text
models
  ↑
repository
  ↑
usecases
  ↑
pages / components
        ↘ services
```

约束：

- 页面可以调用 usecase、repository 和 service。
- Usecase 不引用 ArkUI 组件。
- Repository 不依赖页面。
- Service 不直接写业务表，必要持久化通过 repository。
- 静态方法内不使用 `this`，用类名访问静态成员。
- 禁止 `any` / `unknown`。
- 新页面必须注册 `main_pages.json`。

## 5. 核心模块设计

### 5.1 DatabaseHelper

- 文件：`repository/DatabaseHelper.ets`
- 数据库：`tixing.db`
- 版本：3
- 安全级别：S1
- 单例导出：`dbHelper`
- 初始化：
  - 缓存 ready Promise，幂等。
  - `whenReady()` 供页面等待。
  - 全部公开读写方法入口等待就绪。
  - 建表和索引用 `CREATE IF NOT EXISTS`。
  - `PRAGMA user_version` 记录版本。
  - v2 老库可幂等升级 v3。

主要能力：

- Mistake CRUD、分页、筛选、统计。
- ReviewLog 插入与查询。
- KnowledgeTag / KnowledgeProfile。
- Student / ReminderSettings。
- PointsLog、汇总、幂等 ID 判断、兑换。
- VoiceAskRecord、InterestInsight。
- AnalyticsEvent 脱敏事件。
- 事务封装 `runInTransaction`。

写操作统一返回 `DbResult`：

```ts
class DbResult {
  success: boolean;
  op: string;
  reason: string;
}
```

### 5.2 复习提交

- 文件：`usecases/ReviewSubmitter.ets`
- 输入：错题、评分方式、输入方式、是否正确、用时、幂等操作 ID。
- 流程：
  1. 构造 ReviewLog。
  2. 插入日志。
  3. 查询该错题全部日志。
  4. `MasteryEvaluator` 判定状态。
  5. `ReviewScheduler` 计算下次复习。
  6. 单次 `updateMistake`。
  7. 幂等发放复习、掌握、连击积分。
  8. 写埋点和性能行为。
- 结果包含成功状态、最新掌握状态、是否达成掌握、获得积分和失败原因。

### 5.3 复习排期与掌握

- `ReviewScheduler`：间隔 `[1, 3, 7, 15, 30]` 天。
- `MasteryEvaluator`：
  - 默认最近 2 次连续正确。
  - 至少跨 2 个日历日。
  - 每次用时 <= 基准 60%。
  - 主观自评增加一次要求。
- `StreakCalculator`：按活动日计算连续学习，支持今天未学习时从昨天续算。

### 5.4 媒体服务

- 文件：`services/MediaService.ets`
- 相册：`photoAccessHelper.PhotoViewPicker`。
- 拍照：系统 `cameraPicker`，后摄。
- 持久化：
  - 相册 URI 拷贝到 `files/mistakes/img_<id>.jpg`。
  - 拍照保存到 `files/mistakes/cam_<id>.jpg`。
- 质量检测：`CaptureOrchestrator.checkImageQuality`。
- 图片读取：
  - 最长边限制。
  - 解码为 PixelMap。
  - 转 Base64 供多模态 AI。
- 资源释放：
  - fd / ImageSource / PixelMap 均 try-finally。
- 删除保护：仅删除 `files/mistakes/` 下应用拥有文件。
- 临时清理：启动时删除拍照取消 / 失败产生的空 `cam_` 文件。

### 5.5 AI 服务

- 文件：`services/AiService.ets`
- 固定模型：`glm-5.3-flash`
- 固定地址：`https://open.bigmodel.cn/api/paas/v4/chat/completions`
- 配置读取：`common/AiConfig.ets`

主要接口：

```ts
recognizeQuestions(imagePath: string): Promise<AiQuestionBatch>
answerVoiceQuestion(question: string, grade: string): Promise<AiVoiceAnswer>
generateCuriosityReport(records: VoiceAskRecord[], grade: string): Promise<AiCuriosityReport>
generateLesson(...): Promise<AiLesson>
userMessage(e: Object, fallback: string): string
```

`recognizeImage` 与 `recognizeQuestion` 保留为辅助 / 兼容路径，当前录题主流程使用 `recognizeQuestions` 多题结构化识别。

### 5.6 问一问音频

#### 录音

- 文件：`services/AudioRecorderService.ets`
- 采集：`AudioCapturer`
- 格式：PCM WAV
- 采样率：16000 Hz
- 声道：单声道
- 位深：16 bit
- 最长：30 秒
- 存储：`files/voice_asks/ask_<id>.wav`
- 写入流程：
  1. 先写 44 字节 WAV 头占位。
  2. `readData` 回调持续写入 PCM。
  3. 停止后回写 data size 和 RIFF size。

#### 端侧转写

- 文件：`services/CoreSpeechService.ets`
- Kit：Core Speech Kit `speechRecognizer`
- 语言：`zh-CN`
- 模式：offline
- 输入：标准 WAV 中解析出的 PCM。
- 分块：1280 字节。
- 间隔：40 ms。
- 尾块：补零到 1280 字节。
- 超时：45 秒。
- 等待 `onStart` 后才写入，避免启动竞态。
- 结果策略：
  - intermediate result 替换当前临时文本。
  - final result 追加稳定文本。
  - onComplete 返回最终文本。
- 原始录音不删除，转写失败也保留。

#### 回放

- 文件：`services/AudioPlaybackService.ets`
- 使用 `AVPlayer` 播放本地 WAV / MP3。
- 页面销毁时停止并释放。

### 5.7 好奇星球聚合

- 文件：`usecases/CuriosityAggregator.ets`
- 本地计算：
  - 总数、周数。
  - 领域 / 主题 / 标签计数。
  - Top 排序。
- AI 生成：
  - 孩子总结。
  - 家长观察。
  - 三条活动建议。
  - 趋势。
- AI 不参与计数，防止幻觉改变统计事实。

### 5.8 提醒服务

- 文件：`services/ReminderService.ets`
- 首选：`reminderAgentManager` 代理提醒。
- 降级：`CalendarReminderService` 写系统日历。
- 同步流程：
  1. 读取设置。
  2. 清理旧代理提醒。
  3. 检查应用通知。
  4. 通知可用则发布代理提醒。
  5. 受限或失败则清理并写日历。
  6. 两者均失败时返回错误。
- 设置关闭时同时清理代理提醒和日历提醒。
- UI 上免打扰模式已移除；提醒开关关闭时其他设置置灰。

### 5.9 数据迁移服务

- 文件：`services/DataPortabilityService.ets`
- Bundle app：`tixing`
- Bundle version：3
- 导出格式：zip
- 最大导入：100 MB
- 预览限制：错题和问一问各 10 条。
- 导出保留：3 份。
- 解析：taskpool。

## 7. 外部 AI 接口合同

### 7.1 HTTP 请求

```http
POST https://open.bigmodel.cn/api/paas/v4/chat/completions
Content-Type: application/json
Authorization: Bearer <apiconfig.json 中的 apiKey>
```

基础 body：

```json
{
  "model": "glm-5.3-flash",
  "messages": [
    {
      "role": "user",
      "content": []
    }

  "temperature": 0.1,
  "max_tokens": 4096,
  "thinking": {
    "type": "enabled",
    "clear_thinking": false
  },
  "reasoning_effort": "low"
}
```

超时：

- connect：30 秒
- read：90 秒

### 7.6 响应处理

1. 解码 response body。
2. 校验 HTTP 200。
3. JSON parse。
4. 读取 `choices[0].message.content`。
5. `extractJson` 去除可能的 markdown 包裹。
6. 结构化 JSON parse。
7. 字段归一化和兜底。
8. 技术诊断写 HiLog。
9. 用户提示经 `AiService.userMessage` 转中文。

### 7.7 配置文件

位置：

```text
harmonyos/entry/src/main/resources/rawfile/apiconfig.json
```

格式：

```json
{
  "apiKey": "your-api-key"
}
```

实现细节：

- 支持 `apiKey` / `api_key`。
- 自动去除 `Bearer ` 前缀。
- 优先用正则从原始文本提取，避免个别真机 JSON 属性访问异常。
- 成功读取后进程内缓存。
- 空 key / 解析失败不会永久锁死当前进程，后续可重试。
- 只记录 key 长度，不记录 key 内容。
- 文件不入库。

## 9. 可观测性与错误设计

### 9.1 日志域

服务均有独立 HiLog tag，例如：

- `TiXing`
- `TiXingDb`
- `TiXingAiConfig`
- `TiXingAiService`
- `TiXingAudioRecord`
- `TiXingCoreSpeech`
- `TiXingCapture`
- `TiXingLessonVideo`
- `TiXingReminder`
- `TiXingCalendar`

### 9.2 记录原则

- 请求前记录关键输入规模，不记录敏感内容。
- 响应记录 HTTP、长度、耗时、usage。
- 错误记录完整技术诊断。
- 长文本分块输出，避免 HiLog 截断。
- 用户界面只显示中文可执行提示。
- API key、学生原始 ID 不直接输出。

### 9.3 性能监控

- `PerformanceMonitor` 记录 trace、statistic、behavior、fault。
- AI 识别记录结果数量。
- 复习提交记录阶段失败。
- 备份导入导出记录关键行为。

### 11.3 混淆注意事项

Release 保留顶层、文件名和导出混淆，但 **关闭属性名混淆**。原因是 GLM 响应、备份 JSON 和结构化脚本均为运行时动态 JSON；属性混淆会把 `choices` 等字段访问改写为混淆名，导致真实响应被误判为空。

### 12.1 建议共享合同

- 领域实体字段
- 枚举值

- 错误分类

- 原始图片 / 音频保留规则
